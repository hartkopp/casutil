# Casio FX-601P/FX-602P and FX-501P/FX-502P

The keystroke programmable calculators FX-601P/FX-602P and FX-501P/FX-502P
save programs and data through the FA-1 or FA-2 cassette interface. This
document shows how the casutil tools handle these files, how a program is
written with an editor and lists all program codes.

## Files and tools

| File | Contents |
|------|----------|
| `.wav` | a recording of the tape signal, or a file to be played into the FA-1/FA-2 |
| `.bin` | the bytes of the file: header, programs or registers, footer |
| `.prg` | a text listing, which describes the file completely |

| From → to | Tool |
|-----------|------|
| wav → bin | `wav2raw -b recording.wav file.bin` |
| bin → wav | `wave602 file.bin file.wav` |
| bin → prg | `list602 file.bin > file.prg` |
| wav → prg | `list602 -w recording.wav > file.prg` |
| prg → wav | `prg602 file.prg file.wav` |
| prg → bin | `prg602 -b file.prg file.bin` |

```
            wav2raw -b
   .wav  ─────────────►  .bin
         ◄─────────────
            wave602

            list602
   .bin  ─────────────►  .prg
         ◄─────────────
            prg602 -b

   .wav ──list602 -w──► .prg ──prg602──► .wav
```

A listing of `list602` is translated back by `prg602` into the same bytes,
like the source of an assembler. This holds for all recordings of the
calculators, including synthetic codes, damaged headers and register
contents, which are no valid numbers. Behind the footer a recording
contains some bytes 0x00 written by the calculator: `wav2raw` keeps them in
the binary file, `list602` ignores them and `prg602` does not write them.
The lead-in and the timing of a recording are not kept.

### Options

| Tool | Option | Meaning |
|------|--------|---------|
| `list602` | `-w` | read a WAV file instead of a binary file |
| | `-u` | names and characters in UTF-8, e.g. `x²`, `π`, `σn` |
| | `-s` | step numbers as shown by the calculator in WRT mode |
| | `-x` | hex codes of all steps and step numbers, bytes of all registers |
| | `-i` | ignore bytes with parity or framing errors of a recording |
| `prg602` | `-b` | write a binary file instead of a WAV file |
| | `-c<calc>` | calculator: `602`, `601`, `502` or `501` |
| | `-n<name>` | file name, up to 6 characters (FX-601P/FX-602P) |
| | `-f<number>` | file number 0..999, 0 for no name |
| | `-l<time>` | lead-in in tenths of a second, default 50 |
| `wave602` | `-n<name>`, `-f<number>`, `-l<time>` | as with `prg602` |

The options of `prg602` take precedence over the lines `# @...` of the
listing.

## Recipes

Save a tape as text and as binary file:

```
list602 -w recording.wav > program.prg
wav2raw -b recording.wav program.bin
```

Look at the codes of a recording, e.g. synthetic ones:

```
list602 -w -x recording.wav
```

Edit a program from tape and load it into the calculator again:

```
list602 -w recording.wav > program.prg
editor program.prg
prg602 program.prg program.wav
```

Play `program.wav` into the FA-2 and load it with `MODE 3 INV LOAD EXE`,
or with the file number, e.g. `MODE 3 INV LOAD 123 EXE`.

Write a new program with an editor, one step per line. The lines `# @...`
are optional, `# @calculator 602` is the default for the FX-601P and
FX-602P. `#` starts a comment at the beginning of a line or behind the
step:

```
# Area of a circle
# @calculator 602
# @name "KREIS"

P0            # counter
   LBL0
   +
   1
   =
   PAUSE
   GOTO0

P1            # area of a circle
   LBL1
   "Radius?"
   HLT        # enter the radius, continue with EXE
   x^2
   *
   PI
   =
   Min05      # keep the area
   FIX2
   "A=\AR05"  # show the area from M05
   PAUSE
   GOTO1
```

```
prg602 kreis.prg kreis.wav
```

Prepare data registers and load them with `MODE 1 INV LOAD EXE`:

```
# @file data
# @name "WERTE"
M00 = 1.5
M05 = -2.5e-12
MF  = 3.141592654
```

Rename a recording or give it a file number:

```
wav2raw -b recording.wav file.bin
wave602 -nNEW file.bin new.wav
wave602 -f123 file.bin new.wav
```

Move a program of the FX-602P to the FX-502P: list it, set
`# @calculator 502` and translate it. `prg602` warns about alpha text,
passwords, FIX and registers from M20 on, which the FX-502P does not know.
A program of the FX-501P/FX-502P is loaded by the FX-602P directly, see
the table of compatibility in the [README](../README.md).

Check that an edited listing is still translated as expected, the listing
of the new file shows the same text:

```
prg602 -b program.prg new.bin && list602 new.bin | diff program.prg -
```

## The listing format

### File description

`list602` writes comment lines with key and value in front of each file,
`prg602` reads them. Without them, `prg602` creates a file of the FX-602P
(`MODE . 20`) without name, the file type follows from the contents.

| Line | Values | Default |
|------|--------|---------|
| `# @calculator` | `602` FX-601P/FX-602P, `601` FX-601P (data with its 16 registers), `502` FX-502P (256 steps), `501` FX-501P (128 steps) | `602` |
| `# @file` | `program`, `data`, `all` (programs and data), `display` | from the contents |
| `# @name` | `"name"`, up to 6 alpha characters (FX-601P/FX-602P) | no name |
| `# @number` | `0`..`999`, 0 means no name | no name |
| `# @mode` | memory partition `.20`..`.80` of the FX-602P | `.20` |
| `# @rawheader` | all bytes of the header in hex | |

`list602` writes `# @rawheader` only, if the other lines do not describe
the header exactly, e.g. for a name padded with blanks by the FX-602P
simulator, an unknown file type or a damaged file number. `prg602` then
writes these bytes as header, the other lines still define the contents,
e.g. the number of registers. An unknown key is an error, other lines
starting with `#` are comments. A comment may also follow the value.

### Programs

- `P0`..`P9` start a program. A program may also contain steps in front of
  `P0`, which `list602` shows below the heading `No program`.
- The steps follow one per line. Step numbers of 3 digits in front
  (`list602 -s`) and the hex codes of `list602 -x` are ignored. The
  programs jump to labels and programs only, the step numbers are for
  information.
- `#` starts a comment at the beginning of a line or behind the step,
  e.g. `LBL0  # main loop`. The step is read first, so `RAN#`, `"123 #"` or
  `°'"` (DMS in UTF-8) may be followed by a comment as well.
- Steps are written in ASCII or UTF-8 as in the tables below, names of
  steps are also accepted in other case.
- Memory operations: `X<->M`, `Min`, `MR`, `M-`, `M+` followed by the
  register, e.g. `Min05`, `MR1F`, `M+25`. The registers from M20 on take
  2 steps with a prefix F1..F4 (+20, +40, +60, +80). `FIX2` is F1 with
  `RND2`. Programs of the FX-501P/FX-502P are listed with the register
  names of these calculators, `MR5`, `MR.5`, `M+.F`, both forms are
  accepted.
- `IND` in front of a memory operation, GOTO or GSB addresses indirectly.
- `[XX]` is a code without name, e.g. from synthetic programming.
- `Password "AB12"` directly behind the program marker: always 4
  characters, stored in reverse order with 0xEC behind.

### Alpha text

Alpha text is written in quotes, it starts and ends with 0x2B (INV ALPHA).
Characters without ASCII equivalent use escapes, see the alpha table below:

- `\AR05`, `\AR1F`, `\AR25`: display of a register (INV AR 0 5 on the
  keyboard), from M20 on with a prefix in front.
- `\ARL2`..`\ARL11`: display of the registers for parentheses (synthetic,
  L0 is x, L1 is y).
- `\XX`: a code without name, e.g. `\2C` for a prefix without register.
- `\FF` at the end of the text instead of the closing quote: the program
  ends in alpha mode without the closing 0x2B, e.g. `"OFFEN\FF`. No step
  may follow.

### Data and display

- Registers: `M05 = 1.5`, `MF = 3.141592654`, `M1F = -2.5e-12`, on the
  FX-501P/FX-502P also `M5`, `M.5`, `M.F`. The registers for parentheses,
  which the FX-501P and FX-601P save as well, are `[11]`..`[15]`.
  Registers not listed are 0.
- A value is a number, 8 bytes in brackets, or a number followed by its
  bytes. The bytes take precedence; `list602` adds them, if the number
  alone would not give the same bytes, and with `-x`. Hex digits are only
  accepted in numbers marked as `(synthetic)`.
- `Display = 55555` or `Display = "TEXT"` for display data, optionally
  followed by the bytes or the 16 codes in brackets. The FX-602P loads
  such files, but shows 0 afterwards.

Notes:

- `"…"` (0x2B) starts and ends alpha text, INV ALPHA on the FX-602P.
  INV MODE on the FX-501P/FX-502P is NOP (0xFB).
- F1..F4 (0x2C..0x2F) are prefixes for the registers from M20 on, F4 is
  synthetic. 0xEC terminates the password, 0xFF ends the program.
- The synthetic codes in parentheses are displayed like the command named,
  but act differently (E. Welker, Sedezimal-Code, 1982): `(SAC)` like xD,
  `(SAC:)` like xDEL, `(GRA)` like ISZ, `(10^x)` halts like BST, `(e^x)`
  halts on a key pressed, `(SA)` executes the next step and halts. 0xEA
  and 0xEB both display "Error".
- The FX-501P/FX-502P use the same codes, but know no alpha text, password,
  FIX and registers from M20 on. Their registers M.0..M.9 and M.F are
  M10..M19 and M1F of the FX-602P.

## Example

A listing of an "all" file with special cases, as written by `list602`.
The name "DEMO" is padded with blanks (0x7F) as by the simulator, so
`# @rawheader` keeps the header bytes. The registers with 0 are left out,
`prg602` creates the same file from it.

```
# @calculator 602
# @file all
# @name "DEMO"
# @mode .20
# @rawheader 40 1F CE 34 FF 33 33 77

P0
  Password "AB12"
  LBL0
  "Radius?"
  HLT
  x^2
  *
  PI
  =
  Min05
  FIX2
  "A=\AR05"
  PAUSE
  GOTO0

P1
  "\AR25 \AR1F \PI\SM\MU<x>"
  "\2CX"
  "\6A\ARL2\ARL6\BA\ARL7\ARL11"
  (SAC)
  (SAC:)
  (GRA)
  (10^x)
  (e^x)
  (SA)
  NOP
  [EA]
  [EB]
  MR25
  M+1F
  IND
  MR05
  x=F
  GOTO1

P9
  "OFFEN\FF

Data

M00  = 1.5
M05  = 78.53981634
M09  = 0  [99 00 00 00 00 00 00 00]
MF   = [AC 09 00 BB DD BF 78 0D]
M1F  = 1.23456789E-45
```

- P0: a password and normal steps, `FIX2` takes 2 steps.
- P1: register displays `\AR25` (2 steps), escapes, a prefix without
  register `\2C`, registers for parentheses, synthetic commands, `MR25`
  (2 steps).
- P9: a program ending in alpha mode, `09 2B 3E 35 35 34 3D FF`.
- M09: a 0 with exponent (0x99) as stored by the simulator, kept by its
  bytes. MF: leftovers, no valid number.

With `-s`, the step numbers are shown:

```
P0
  Password "AB12"
  001  LBL0
  002  "Radius?"
  011  HLT
```
